# 视觉 UART 原始接收排查

当前配置为 UART3、RX=PA25、TX=PA26、115200、8N1。
调试页直接显示交给解析器之前的字节，不要求先收到合法帧。

## 1. 打开与操作

首页选中 UART raw，按 KEY3 进入。从默认首页按 KEY1 一次也可到最后一项。

- KEY1 / KEY2：在 HEX 与 INFO 两个视图之间切换。
- KEY3：切换 LIVE/HOLD，只冻结最近 24 字节的显示。
- KEY4：返回首页，沿用返回兼停止行为。
- HOLD 时后台仍接收、解析和更新计数；再次确认恢复显示最新字节。

HEX 四行按收到的先后顺序显示，每行六字节。
左边 00、06、0C、12 是这 24 字节窗口的十六进制偏移，不是协议帧内偏移。
窗口可从半帧开始，需在其中查找 55 AA 和 0D；空位置显示 --。

## 2. 读计数

| 字段 | 含义 |
|---|---|
| B / APP | 已交给解析器的字节总数，垃圾数据也计入 |
| A | 距最后一次交给解析器的字节的毫秒数；B=0 时显示 0 |
| HW | ISR 从 UART RXDATA 读出的字节总数，包含软件队列丢弃的字节 |
| DROP | 软件环形队列已满，丢弃的新字节数 |
| OVR | RXDATA 报告硬件溢出的次数，不等于精确丢失字节数 |
| ERR | 接收字节带帧错误、奇偶错误或 Break 错误的次数 |
| SYNC | 相邻字节出现 55 AA 的次数，可能包含载荷中的同样字节 |
| OK | 接受了合法且序号独立的新帧 |
| DUP / D | 合法但 seq 与上一观测相同，未更新观测 |
| T | 以 55 AA 起始的 13 字节候选，尾字节不是 0D |
| C | 尾字节正确但累加校验不符 |
| R | 尾字节、校验正确，但字段超范围 |
| OLD | 短时间内 seq 被判定倒序 |
| BAD | 坏候选和倒序帧的总数 |

校验按 T、C、R 的先后顺序分类，每个坏候选只记第一类失败。
INFO 页计数显示上限为 999999，T/C/R 和 HEX 页 OK/BAD/D 为 9999，
超过后显示上限值，内部 32 位累计值不因此清零。
计数自启动原始接收或 Vision_Init 后累加，HOLD 不清零。

Vision 列表里的 Age 是距最后一个被接受的新帧的年龄；
HEX 页的 A 是字节年龄。只有前者增长，不能断定 UART 没有收字节。

## 3. 如何判断问题在哪一层

- HW 与 B 都不增长：先核对视觉 TX 到 PA25、共地、发送是否持续及 115200/8N1。
- HW 增长但 B 跟不上，DROP 增长：应用消费不及时，查看主循环阻塞。
- OVR 增长：硬件数据未及时读走；ERR 增长：核对波特率、接线和信号质量。
- B 增长而 SYNC 始终为 0：看 HEX，核对是否真发二进制 55 AA。
- SYNC 增长、OK 不增长：结合 T/C/R 看帧长、帧尾、校验或字段范围。
- DUP 增长：接收端看到重复 seq，合法帧不会刷新观测 Age。
- OLD 增长：检查 seq 跳变/重启行为，现有 100 ms 序号重建规则保持不变。

R 检查 elem=0..6、phase=0..3、conf/valid=0..100、lost=0/1，
以及大端有符号 dev_raw=-1000..1000；k 按有符号 int8 解码。

## 4. 一组已知合法数据

```text
55 AA 01 00 00 00 00 00 5A 64 00 BF 0D
55 AA 02 00 00 00 00 00 5A 64 00 C0 0D
```

两帧分别 seq=1、2，dev/k=0，conf=90、valid=100、lost=0。
串口助手需使用 HEX 发送；文本形式的 55 AA 会变成 35 35 20 41 41。

## 5. 本次接收路径调整

原始模式启用硬件 FIFO，RX 阈值设为一个字节，并配置接收超时事件。
每次 ISR 最多读 16 个已有字节，不等待后续字节到达。
RXDATA 一次读取同时取得数据与错误位，避免先读错误再读数据而重复出队。
软件满队列丢弃新字节并记 DROP，ISR 不再修改主循环拥有的 tail。
可用字节数使用 head/tail 的局部快照，避免计算中被接收中断改变。

这些调整补强了接收能力；本次实机异常的具体原因仍需结合调试页确认。
