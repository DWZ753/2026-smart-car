# 主控端修改清单（视觉接口 · 对齐版）

> **适用文件**：`modules/vision/vision.c`、`application/race/race_control.c`
> **协议文档**：`vision.md`（13 字节帧）
> **视觉端状态**：`try_v6.py` 已完成下方 V1~V5 并部署
> **结论**：帧的**编码层不需要改**（6/6 个协议示例帧逐字节一致）；
> 要改的是**语义层**——`lost` 怎么对待、`valid` 用来干什么、时限怎么定、`k` 变了之后 KH 怎么标。

---

## 0. 视觉端本次已经改了这些（主控按新行为设计即可）

| # | 视觉端改动 | 主控会看到什么变化 |
|---|---|---|
| **V1** | 斑马线 `conf` 30 → **90**，且不再按行质量打折 | `elem=5` 时 `conf=90` **恒定**，满足 `CAR_ELEMENT_CONF_MIN=70` |
| **V2** | `seq` 改为**感知序号**（主循环 `frame_id`）；只在新感知时发帧 | 帧率约 **30~34 Hz**（不再是 50 Hz）；**不会再出现重复 seq** |
| **V3** | `LOST_RATIO` 0.25 → **0.12**；`LOST_RECOVER_RATIO` 0.40 → **0.25** | `lost=1` 只在 `valid < 12%`（真丢线）时出现，宽赛道/全白不再误报 |
| **V4** | `TRACK_W_BOTTOM_PX = 276`（现场标定值） | 单边行算出的中心稳定，`dev` 抖动下降 |
| **V5** | `k` 已扣掉"横向偏移"分量（`K_DEV_RATIO=0.78`） | **k 的量级明显变小**；直道横偏时 `k≈0`。**KH 必须重标** |

> ⚠️ V2 之后主控看到的帧率是 30~34 Hz（不是 50 Hz）。这是**正常**的，
> 不要因为 DUP 计数为 0、帧率下降就以为视觉出问题。

## C1（P0）`lost=1` 不要立刻冻结转向，改成"保持 + 衰减"

### 现在的问题

`vision.md` §2.3 / §3.3：收到 `lost=1` 立即冻结转向并降速，100 ms 无可用帧即 `RACE_FAULT`。
视觉端的 `_lowvis` 带迟滞（进 12% / 出 25%），画面一旦进入"整片全白"就会持续一段时间，
很容易超过时限 → **整车故障停车，需要重新 Start**。车上表现就是"突然没方向、停死"。

### 改成

```c
/* 收到 lost=1：保持最后一帧可用舵量，300 ms 内线性衰减到 0，不要立即冻结 */
if (vision.lost) {
    uint32_t held = now_ms() - vision.last_good_ms;
    if (held < 300) {
        turn = vision.last_turn * (1.0f - 0.2f * (float)held / 300.0f);
    } else {
        turn = 0.0f;
    }
    speed_target = DEGR_SPEED;      /* 降速可以保留 */
}
```

### 验收

注入 **150 ms** 的 `lost=1` 注入后立刻恢复正常帧 → **车继续行驶**，不进入需要重启的故障态。

## C2（P0）`RACE_FAULT` 增加自动恢复

### 现在的问题

`RACE_FAULT` 之后两轮制动、舵机回中，**必须人工重新 Start**。
赛道上任何一次 100 ms 的视觉不可用都会让这一轮跑废。

### 改成

```c
/* 故障后不要求人工 Start：视野恢复即自动退出 */
if (race.state == RACE_FAULT &&
    vision.sample_id != 0 &&
    !vision.lost && vision.elem != 6 &&
    consecutive_usable_frames >= 3) {
    race.state = RACE_RUN;
    turn = vision.last_turn;        /* 从当前舵量斜坡恢复，不要瞬跳 */
}
```

### 验收

注入 **600 ms** `lost=1` → 停车；随后恢复正常帧流 → **自动重新起步**。

## C3（P0）时限按 30~34 Hz 重定

### 现在的问题

| 常量 | 现值 | 问题 |
|---|---:|---|
| `CAR_VISION_SLOW_MS` | 50 ms | 视觉周期 29~33 ms，余量只有 ~17 ms，一次慢帧就冻结转向 |
| `CAR_VISION_STOP_MS` | 100 ms | 约 3 个周期，太紧，与 C2 的"自动恢复"一起调 |

### 改成

| 常量 | 现值 → 建议 |
|---|---|
| `CAR_VISION_SLOW_MS` | 50 → **80** |
| `CAR_VISION_STOP_MS` | 100 → **300** |

### 验收

单次 40 ms 慢帧 → 不冻结转向。

## C4（P0）`valid` 只做转向权限缩放，不触发故障

### 现在的问题

`valid < 15` 直接判"几何不可用"，并计入停车倒计时。
但视觉端的 `valid` 是**可用行比例**，在"赛道比画面宽"时天然偏低：

| 场景 | 视觉实测 `valid` |
|---|---|
| 普通直道 | 100 |
| 宽赛道单边 | 77 |
| 十字路口全白 | 24 |
| 真丢线 | 0 |

`24` 距离门限 `15` 只有 9 个点余量 —— 稍有噪声就掉到门限以下 → 停车。

### 改成

```c
/* valid 只缩放转向权限，不参与故障判定 */
float authority = 1.0f;
if (vision.valid < 40)
    authority = 0.5f + 0.5f * (float)vision.valid / 40.0f;
turn = clamp((KP * dev + KH * k) * authority, -Limit, Limit);

/* 故障只由 lost / elem==6 触发（并按 C1/C3 处理） */
```

### 验收

连发 200 ms 的 `valid=10 / lost=0 / elem=0` → **不停车**，转向权限降到约 60%。

## C5（P0）配合 V5 重标 KH

### 为什么必须做

视觉端把 `k` 里的**横向偏移分量**扣掉了。原来直道横偏时 `k ≈ −0.78·dev`，
和 `KP·dev` 正好对着干；现在直道上 `k≈0`，**同样的 KH 会让直道"突然变有力"**。

### 怎么标

1. 车摆**直道**、横向摆偏（屏幕 `dev ≈ ±0.8`）；
2. 看视觉屏幕：`k` 应该显示 **±0.0x**（不是 ±0.15 以上）。若不是，调视觉端
   `K_DEV_RATIO`（偏正就调大、偏负就调小）直到 ≈0；
3. 主控重标 **KH**：直道如果开始来回摆，先把 **KP 降到 0.7 倍**再微调 KH。

### 验收

直道横偏 → 舵机明显往中线方向反打，不摆。

## 对齐后的字段契约（建议补进 `vision.md`）

| 字段 | 视觉端行为（本次之后） | 主控应当怎么用 |
|---|---|---|
| `seq` | **感知序号**，重发不变 | 相同 seq 视为重复帧，不刷新 `received_ms` |
| `valid` | 可用行比例（几何质量，0~100） | **只缩放转向权限**，不触发故障 |
| `lost` | 只在 `valid < 12%`（真丢线）时为 1 | 保持+衰减（C1），不立即故障 |
| `elem=6` | 等同 `lost=1` | 同上 |
| `conf` | 斑马线恒为 **90** | 只用于终点判定（阈值 70） |
| `elem=3/4` | **目前基本不会出现**（环岛识别做不到） | **不要依赖**，环岛仍需另想办法 |
| `elem=2` | 全白十字：`dev` 冻结、`k=0`、`conf=85`、`lost=0` | 按"直行"处理即可 |
| 帧率 | 30~34 Hz | `SLOW/STOP` 按此重定（C3） |

## 视觉端的已知限制（主控端别指望）

1. **环岛识别做不到**：你这套安装几何下（赛道比画面宽、上部 28% 不扫描），
   环壁不在视野里或不被扫描，靠"边界阶梯"判不出来。`elem=3/4` 目前形同虚设。
2. **入环口 / 十字正中画面全白时，`dev` 没有物理意义**（但 `conf` 不低）——
   所以主控**不要用 `conf` 判断循迹质量**（协议本来也是这么规定的，正好一致）。
3. `dev` 是"逐行加权平均 + 45% 前瞻"，比车头真实偏移**小 30~50%**，KP 只能在一个工作点上标。

## 附录：帧编码兼容性（已通过，无需改动）

用 `vision.md` §5 的 6 个合法示例帧喂给视觉端的 `make_frame()`：

```
OK  普通 dev=0 k=0 conf=90 valid=100
OK  普通 dev=-0.300 k=-0.12 conf=90 valid=80
OK  斑马线 elem=5
OK  丢线 lost=1
OK  急弯 dev=+0.5 k=+0.2
OK  左环入环 phase=1
逐字节一致: 6 / 6
```

现场实测帧（可直接做解析器单元测试）：

```
视觉端输出: NORMAL, dev=-0.809, k=+0.630, conf=73, valid=100, lost=0
55 AA 01 00 00 FC D7 3F 49 64 00 C0 0D
                └─ dev = 0xFCD7 = -809 (int16) ─┘  k = 0x3F = +63 (int8)
```

如果解析出 `dev = +64727`，说明按 **uint16** 读了，需要 `(int16_t)` 强转。
